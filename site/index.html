Put your MCP servers on a URL.

Most MCP servers are stdio programs, and stdio only works when the client can spawn the process itself. Your phone can't. mcpelevator runs those servers in one self-hosted container and gives each one an authenticated Streamable HTTP endpoint. Add a server, press start, copy the URL.

    Without it

    A stdio server lives inside whatever launched it. That's fine for a desktop client on the same machine. Claude mobile, a browser, or a box across the room has no way to run npx for you, so the server might as well not exist.

    # only works where the client can spawn it
npx -y @modelcontextprotocol/server-memory
    With it

    mcpelevator keeps the process running on your own hardware and hands back a URL. Anything that speaks Streamable HTTP can use it, and stdio-only clients can still reach it through mcp-remote.

    https://mcp.example.com/s/memory/mcp

    How it works

    One container, one port, a bridge per server.

    FastMCP does the protocol bridging. mcpelevator is the control plane around it: it supervises the processes, puts auth in front of them, and gives you a UI to run it all from.

    01 Add

    Paste a launch command, a Docker image, a remote URL, an OpenAPI document or a GraphQL endpoint. Or paste a whole mcpServers config, or install straight from the public MCP registry.

    02 Start

    Each server gets its own bridge process on a loopback port, with a real PID and its own log. One crashing server doesn't take the others with it. If a start fails, the last error and the log tail tell you why.

    03 Copy

    The copy menu has a ready config for Claude Code, Claude Desktop, Claude web and mobile, Codex, ChatGPT, Gemini CLI, VS Code and plain mcpServers. Paste it and you're connected.

    Runners

    If it can become MCP tools, it can go on a URL.

    Every runner is just a different way to get a server started. They all end up behind the same auth, supervision and copy menu.

    npx

    npm packages

    Node and npx ship in the image, so npx -y … servers run with no extra setup.

    uvx

    PyPI packages

    Python servers run through uv. A native build toolchain is in the image for packages that compile on install.

    command

    Anything you can type

    Any command line, including a server cloned from a GitHub repo and built from its own checkout.

    docker

    Container images

    Runs images with a locked-down docker run. Off by default, since access to a Docker daemon is root-equivalent.

    remote

    Already-remote MCP

    Proxies an existing HTTP or SSE MCP URL behind your own auth. Sign in to the upstream with headers or OAuth.

    openapi

    REST APIs

    Point it at an OpenAPI document and every operation becomes a tool. No MCP server needed upstream.

    graphql

    GraphQL APIs

    Each query and mutation field becomes a tool, validated against the schema before it's sent.

    mcpelevator

    It manages itself, too

    A built-in control server lets an agent install servers, read logs and mint tokens, with the caller's own permissions.

    Features

    The parts you'd otherwise end up building yourself.

    Getting a stdio server onto HTTP is the easy part. Keeping a dozen of them up, locked down and debuggable is where the time goes.

    Supervision that explains itself

    SQLite holds the state you asked for and a supervisor keeps converging the real processes to it, Kubernetes-style. Restart the container and everything comes back the way it was. When a server fails, its last error and log tail are right there on the card.

    Running Starting Unhealthy Failed Idle Stopped

    Idle shutdown, wake on request

    A server nobody has called in a while gets stopped. The next request wakes it and waits until it's ready, so the client just sees a slower first call.

    Write-only secrets

    Mark an env var or header as secret and it's encrypted at rest and reads <hidden> from then on. It gets decrypted in one place, right before launch.

    Groups

    Bundle servers behind one URL at /g/<name>/mcp. Tools get prefixed with the member's slug, and connected clients hear about membership changes right away.

    Tool policy

    Hide a tool, rename it, rewrite its description, or add aliases so old names keep working. One transform applies it to MCP, REST and groups at the same time.

    A REST mirror

    Turn on REST for a server and every tool is also a plain call at /s/<slug>/rest/<tool>, with a generated openapi.json for curl, automations and GPT Actions.

    A catalog to install from

    Browse the official MCP Registry and Glama from the UI, pick a version, review the launch spec, install. A local mirror keeps browsing working when a directory is down.

    Usage per tool

    Hourly call counts for every server and tool. Arguments are never recorded. You find out which tools get used and which ones nobody has ever touched.

    Health checks

    Call a cheap tool or run a shell command at startup and on an interval, so "running" means it answers, not just that the process exists.

    Launch from a repo

    Not on npm or PyPI? Give it a GitHub URL. It clones the repo, runs the build steps it detects, and starts the server from that checkout.

    More than one person

    Admins and members with login tokens. Members see and manage only their own servers, and a server they can't see returns 404 like it isn't there.

    Security

    Locked down by default, upfront about the limits.

    Two independent layers check every request. Both have to pass.

    Host/Origin allowlist, always on

    Blocks DNS rebinding in every mode. A loopback Host only counts when the connection really comes from loopback, so an exposed box can't be fooled by Host: localhost.

    Per-server auth

    none, bearer or oauth. Tokens can be scoped to one server, one group, or everything. They're stored as SHA-256 hashes and shown exactly once.

    Control plane auth turns itself on

    In the default auto mode, /api starts requiring an admin token as soon as the config says the box is reachable off-host. A plain local install stays zero-config.

    Docker runner is opt-in

    When you do turn it on, containers run with --cap-drop ALL, no-new-privileges, a PID limit and a memory cap, and secrets never land on mcpelevator's own command line.

    Authorization, not isolation. Local runners execute as the mcpelevator process user and can read its data directory, including other servers' settings. Multiple users split up who manages what. They don't sandbox servers from each other. Only give the local-runner permission to people you'd trust with the machine.

    Quickstart

    Get it running.

    Everything ships in the one image: Node, npx, Python, uv and a native build toolchain. Nothing else to install on the host.

    $ git clone https://github.com/pacnpal/mcpelevator
$ cd mcpelevator
$ docker compose up --build
# then open http://127.0.0.1:8080

    The port is published to host loopback only, and data lives in the mcpe-data volume. Read Security before you open it up to your network.

    Install mcpelevator from Community Applications. The template lives in pacnpal/unraid-templates and comes set up for a headless box: host networking so the LAN gate sees real client IPs, appdata at /mnt/user/appdata/mcpelevator, and LAN access on from the first boot.

    # the first boot prints an admin token, once
$ docker logs mcpelevator 2>&1 | grep -A2 "control-plane auth is ON"

    The full walkthrough covers first login, updating and troubleshooting: docs/unraid.md.

    # control plane on http://127.0.0.1:8080
$ cd backend && uv sync && uv run uvicorn app.main:app --reload

# UI with hot reload on http://localhost:5173
$ cd frontend && npm install && npm run dev

    The Makefile wraps these: make dev-backend, make dev-frontend, make test.

    Connect a client

    Clients that speak Streamable HTTP take the URL directly. For one that can only launch a local command, put mcp-remote in between:

    {
  "mcpServers": {
    "memory": {
      "command": "npx",
      "args": ["-y", "mcp-remote",
        "https://mcp.example.com/s/memory/mcp"]
    }
  }
}

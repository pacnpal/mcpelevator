# Generic stdio client bridge documentation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Explain how any stdio-only MCP client can reach a remote mcpelevator server or group through `mcp-remote` on Windows, macOS, or Linux.

**Architecture:** Add one client-neutral README section immediately after the first elevated-server URL example. Reuse the same `mcp-remote` invocation and Windows-safe bearer-header shape already generated by `frontend/src/lib/install.ts`.

**Tech Stack:** Markdown, JSON, Node.js/npm (`npx`), Vitest

**Spec:** `docs/superpowers/specs/2026-08-22-generic-stdio-client-bridge-design.md`

## Global Constraints

- Make no backend, frontend, dependency, binary, or packaging changes.
- Support Windows, macOS, and Linux through the existing Node.js `npx` launcher.
- Limit plain HTTP guidance to loopback or trusted private networks.
- Keep bearer secrets in the client entry's `env`, with `Authorization:${AUTH_HEADER}` as the argument.
- Cover both `/s/<slug>/mcp` server URLs and `/g/<name>/mcp` group URLs.
